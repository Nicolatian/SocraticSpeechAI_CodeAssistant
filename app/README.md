# React + Vite

This template provides a minimal setup to get React working in Vite with HMR and some Oxlint rules.

## Running the website

The dev container provides Node.js 22 and npm. After changing the Dockerfile,
run **Dev Containers: Rebuild Container** from the VS Code Command Palette.
Then, from the `app` directory, install the project dependencies and start Vite:

```bash
npm ci
npm run dev
```

Open the URL printed by Vite to use the website.

## Running the local LLM prompt page

The assistant can read each new response aloud using Plapre Nano. Plapre
requires Python 3.12+, a CUDA GPU, and access to the gated
[syvai/plapre-nano model](https://huggingface.co/syvai/plapre-nano). Keep TTS
in its own `venv-tts`; do not install it into the system Python or
`venv-mimir`, which the model server uses with a different CUDA/PyTorch stack.

The NVIDIA GB10 container uses CUDA 13.1, while Plapre's vLLM 0.15 stack uses
CUDA 12.8. In `venv-tts`, install the matching GPU packages before Plapre so
pip does not select CPU-only PyTorch:

```bash
/workspace/venv-tts/bin/python -m pip install \
  --index-url https://download.pytorch.org/whl/cu128 \
  "torch==2.9.1+cu128"
/workspace/venv-tts/bin/python -m pip install \
  --force-reinstall --no-deps \
  --index-url https://download.pytorch.org/whl/cu128 \
  "torchaudio==2.9.1" "torchvision==0.24.1"
/workspace/venv-tts/bin/python -m pip install -r /workspace/requirements.txt
```

Log in to Hugging Face with a read token that has gated-repository access, then
verify that CUDA is available:

```bash
/workspace/venv-tts/bin/hf auth login
env -u LD_LIBRARY_PATH /workspace/venv-tts/bin/python -c \
  'import torch; print(torch.__version__, torch.cuda.is_available())'
```

`prompt_server.py` handles the CUDA environment automatically when it starts:
it relaunches in `venv-tts` and removes the container's CUDA 13 library path.
This keeps the TTS CUDA 12.8 libraries separate from the model server's stack.

Speech is generated by the local prompt API on the first assistant response.
The response includes audio playback controls; browsers that block autoplay
can still play it manually. If speech generation fails, the text response is
kept in the chat and the speech error is shown.

Chat answers stream into the page as Ministral generates them. Once the full text
answer is ready, the frontend sends it to Plapre in one request. Plapre batches
the answer's sentences into a single audio file, avoiding separate playback
clips and repeated speech requests. Speech therefore starts after text
generation finishes.
After code changes, restart `prompt_server.py`; restart `start_llm.py` only if
its code changed. Vite reloads frontend changes automatically.

From the workspace root, start the local model server with `python start_llm.py`.
In a second terminal, also from the workspace root, start the prompt API and
TTS with `python prompt_server.py`. It automatically uses `venv-tts`. Then run
the React app from this directory with `npm run dev`. Open `/MainPage`, edit
the code, type a question, and select **Send**. The current editor contents
are sent with the question, and the LLM response appears in the chat history.
Code longer than 20,000 characters is rejected with an error. The page
confirms how many editor characters the API received. If it reports that the
API did not confirm the code, restart `prompt_server.py` so it loads the
latest version. When the editor is unchanged, the API avoids including a
duplicate copy of the previous code in the model prompt.

The Vite development server proxies `/api` requests to the local prompt API on
port 8001; the API calls `ask()` from the root `prompt.py` script.
The prompt API is not the website: opening `http://127.0.0.1:8001/` directly
returns service status. Open the URL printed by Vite to use the application.
Chat history is kept in memory only for the currently selected exercise. It is
cleared when you switch exercises or reload the page, and is never saved in
browser storage. The latest six exchanges are sent to the model as context, and
**Clear history** clears the current exercise's conversation.

Exercise starter code, learner-facing instructions, and explanation are defined
by category in `src/exercises.js`. Selecting a category displays its explanation
without sending the solution or answer key to the LLM. The exercise description
is included as context when the learner asks a question.
Saved conversations include the selected exercise ID. Run `python export_logs.py`
from the workspace root to refresh `pear_exports/conversations.csv` and create
one `conversations_<exercise-id>.csv` file for each exercise represented in the
logs. Conversations saved before exercise tracking was added have a blank
exercise ID and are included only in the combined export.

Currently, two official plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses [Oxc](https://oxc.rs)
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses [SWC](https://swc.rs/)

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).
